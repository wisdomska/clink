# Clink build plan and traceability map

Clink is a Next.js 15 (App Router, TypeScript) PWA on Vercel, backed by Supabase (Postgres with RLS, Auth, Realtime, Storage, pg_cron), tested with Vitest, Playwright and axe-core.

This page maps every requirement ID in the MVP spec (`docs/spec/Clink - MVP Product Specification.docx`, sections 6 and 7.4) and every screen and state in the v2 prototype (`Clink Prototype v2.dc.html` in `design/`) to the code that implements it and the tests that verify it.

How to read the tables:

- **Route(s)**: page routes under `src/app` (route groups are omitted from the URL: `(app)/us` serves `/us`), plus the API route handlers that enforce the rule.
- **Component / module**: the main client component in `src/features/*` and any server helper in `src/lib/*`.
- **Tables**: Postgres tables from `supabase/migrations/*.sql`. Seeded content lives in `supabase/seed.sql`.
- **Tests**: `e2e/` is `tests/e2e/*.spec.ts`, `unit/` is `tests/unit/*.test.ts`, `rls` is `tests/rls/rls.test.ts`, `a11y` is `tests/a11y/routes.spec.ts`. "a11y only" means the route is rendered and axe-checked but the behaviour itself is not asserted.
- **Status**: "Done" (meets the acceptance criteria as far as the code shows), "Partial: what is missing", or "Not built: why".

Every table in `supabase/migrations` is also covered by the RLS coverage test (`rls`, "every public table is in the RLS matrix and has RLS enabled"), so `rls` is only listed below where a requirement has its own rule-specific RLS assertion.
